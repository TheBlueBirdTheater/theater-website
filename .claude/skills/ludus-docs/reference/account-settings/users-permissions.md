# Users - Permissions

## Overview

User is the term for anyone who has internal access to your Ludus account. You can set up as many users as you'd like on your account.

### Types of Users

There are 4 types of users within your Ludus admin panel.

-   **Super Admin**: This user has full privileges to all features and account settings.

-   **Admin**: This user has full account management privileges, except for account settings.

-   **Seller**: This user has sales capabilities on the admin panel. They can also refund orders if allowed (see below)

![Document image](https://images.archbee.com/hZcZIA5As4EsukOh0OMVE/C4gIsmC7_iNkPaEUHxH4X_screenshot-2026-07-14-at-112825-am.png?format=webp "Document image")

-   **Viewer:** This user can view sales and info, but not make any changes.

-   This is the perfect level if you hope to share reports but do not want to allow edit access.

It is recommended that each user have their own profile. For example, if you have multiple sellers, you can enter them as **Seller1**, **Seller2**, and so on. This will not only help with reporting but will also keep things clear on your Ludus account.

### Access Levels

Access levels are a second tier of permissions that gets a bit more granular. Every Admin user has a combination of “Admin Type + Access Level”. If their “Admin Type” has access to a certain page or feature, but their Access Level does NOT, they will not be able to access it. If you are a Super Admin type → you will not need to select an Access Level (you will have access to everything no matter what). There are 3 Access Levels:

-   **Everything** → Full site access contextual to the Admin Type permission already granted. Super Admins will always have everything applied to them

-   **Limited** → This allows org admins to give users special access to **ONLY** the core features they should be using. If an admin has limited permissions, they will only be able to access a feature if it is selected in the list of core features.

-   A limited number of users can have as many or as few features as needed for their specific use. These are selected from a drop-down that appears once Limited is selected.

![Document image](https://images.archbee.com/-Wjcg2-gpBfUKvBZQaMyV-KtiBHOQk0ZBiy9nD7H4tR-20241111-194423.png?format=webp "Document image")

-   **Guest** → This allows org admins to give their users special access to ONLY specific listings they should have access to. This is for special cases where you want a user to be able to edit and/or sell only for a specific event, class, or collection, but not manage, sell, or view any other listings.

-   Guest Users can be granted access to specific events, Classes, or collections, which you can select once a Guest is chosen.

![Document image](https://images.archbee.com/-Wjcg2-gpBfUKvBZQaMyV-SP1sBfN5LIdlJwnvoHE6B-20241111-194524.png?format=webp "Document image")

### Examples:

**‘Admin’ Type w/ Guest Access for Wizard of Oz:** - Will be able to edit all details for this event - Will be able to add/remove showtimes for this event - Cannot view any other event/class/etc - Cannot access \`Utility\` globals since it touches other listings they don’t have access to. However, they can apply existing global discounts to their sales. - Access to reports on mobile apps **‘Seller’ Type w/ Limited Access for Volunteers:** - Will only see Volunteer Management & Patron/VM profiles in their admin portal - Will not be able to edit, view, or sell events/classes/collections - Can sign up volunteers for opportunities (sell action) - Cannot create new volunteer opportunities (this is a ‘creator +’ action) - No access to reports on mobile apps **‘Viewer’ Type w/ Guest Access for all active classes:** - Will be able to see all classes in the system - Able to open patron profiles linked to sales for all classes - Cannot view/sell for any events or standard collections - Cannot access marketing, fundraising, or VM features - No access to reports on mobile apps ‘**Admin’ Type w/ Limited Access for Events, Collections, Classes:** - Will be able to create, edit, sell, and view any listing for an event, class, or collection - Can view patron profiles - No access to Volunteer management, marketing, fundraising, etc - Access to reports on mobile apps
