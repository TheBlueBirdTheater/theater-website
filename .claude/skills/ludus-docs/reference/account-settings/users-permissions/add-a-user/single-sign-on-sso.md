# Single Sign-On (SSO)

Single Sign-On (SSO) allows Ludus admins to securely connect to the Ludus application using their organization's secure authentication protocols. This also removes the need to remember separate Ludus-specific usernames and passwords; instead, admins can sign in once with a single set of login credentials. This simplifies the login experience, reduces password-related issues, and helps organizations improve security and user management.

_**To enable Single Sign-On**_, reach out to the [Live Chat Support](https://support.ludus.com/live-chat-support) team and they can assist with turning that on for your account.

Once enabled, you can set up SSO for your users.

1.  Go to **Settings** (gear at the top of your account) -> **Users**.
    
    ![Document image](https://images.archbee.com/hZcZIA5As4EsukOh0OMVE/7tUjr8F3Y3vanN9xkU9uW_screenshot-2026-08-11-at-93125-am.png?format=webp "Document image")
    
2.  On the Users tab, you will want to select **SSO**, to be able to turn on Single Sign-On for your account.
    
    ![Document image](https://images.archbee.com/hZcZIA5As4EsukOh0OMVE/8pdV8Ifw83OLl2QFn5b6I_screenshot-2026-08-11-at-92846-am.png?format=webp "Document image")
    
3.  Under the **SSO** tab, you will have 2 options:
    
    1.  **Enable Single Sign-On (SSO)** - Allow admin users to sign in via your organization's identity provider (e.g. Okta, Google Workspace). SSO must be configured for your site by Ludus before you can enable it here.
    
    2.  **Force SSO** - When enabled, admin users can only sign in via SSO; username/password login is disabled. At least one admin must have signed in with SSO at least once before you can enable this, or you may lock yourself out.
    
    _**Forcing SSO**_ - If you already have existing admins in your Ludus account, you will need to make sure their email addresses belong to your organization domain, otherwise they will no longer be able to access Ludus.
    
    Once you select which of these you wish to utilize, select **Save**.
    
    Once this is saved, _you will need your IT administrator to provide you with whitelisted domains_ (for example, "@ludus.com"), as these will need to be shared with Customer Support.
    
4.  When you have received confirmation of the final setup from Customer Support, your team will be able to utilize this for your account.
