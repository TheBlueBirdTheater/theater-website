# Add-Ons Report

The Add-Ons report is a versatile report that lets you view sold Add-Ons, mark items as fulfilled, and view general totals for each Add-On variation. This report can be viewed account-wide or for a specific event, collection, or class. Additionally, you can mark Add-Ons as fulfilled through this report.

There are two main views for Add-On reports

-   **All**/**Open**/**Fulfilled** - This will show each add-on purchased as a separate row on the report

-   **Summary** - An overview of the sales totals for each variation of add-ons.

## View Add-Ons Report

Follow the instructions below to pull an Add-Ons report for the desired domain.

-   **Global Add-Ons Report** - To pull an account-wide Add-Ons report, click **Reports** (from the top navigation bar) --> **Add-Ons**.

-   **Event Add-Ons Report** - To pull an event-specific Add-Ons report, click the **Events** tab from the top navigation bar. Then, click **Reports** --> **Add-Ons** next to the desired Event.

-   **Collection Add-Ons Report** - To pull a collection-specific Add-Ons report, click **Collections** --> **Standard** from the top navigation bar. Then, click **Reports** --> **Add-Ons** next to the desired Collection.

-   **Class Add-Ons Report** - To pull a class-specific Add-Ons report, click **Collections** --> **Classes** from the top navigation bar. Then, click **Reports** --> **Add-Ons** next to the desired Class.

Check out the drop-downs below to learn more about the different views available for Add-Ons reports. Both views are available on Global, Event, Collection, and Class Add-Ons reports.

## All/Open/Fulfilled View (Add-Ons)

The All, Open, and Fulfilled tab at the top of the Add-Ons report allows you to view each purchased add-on as a separate row in the report.

There are two statuses for Add-Ons. Open means it has not been processed or given to the patron, while Fulfilled signals that it has. You can use these statuses to track add-ons in a way that works best for your needs.

There are multiple ways to "fulfill" add-ons. From this report, you can use the checkboxes in the far left column and then use the drop-down menu in the upper right-hand corner to change the status to open or fulfilled.

### Terms and Definitions in the All/Open/Fulfilled View

-   **Status** - Whether the order is "Open" or "Fulfilled"

-   **Order I.D.** - The code associated with the order used for internal tracking. (Click the code to open the order summary for the purchase)

-   **Item** - The variation of the add-on that was purchased.

-   **Patron** - The name of the patron who made the purchase**.**

-   **Email** - The email associated with the purchase.

-   **Event** - The event, class, or collection to which the add-on belongs. Includes event time or class time.

-   **Attached Seat** - The seat number associated with the add-on (if applicable). \*This is most common for add-ons that are attached to ticket prices.

-   **Student** - The student to which the sale is credited (if enabled).

-   _Suggested Article_: [Student Credit](https://support.ludus.com/student-credit)

-   **Order Date** - The date and time the purchase was made.

-   **Price** - The original price of the add-on.

## Summary View (Add-Ons)

The Summary view is the best way to see grand totals for each add-on variation being sold.

![Document image](https://images.archbee.com/hZcZIA5As4EsukOh0OMVE/aBnrq6-4CYxYvNO2p6ORc_screenshot-2023-12-13-at-41705-pm.png?format=webp "Document image")

### Terms and Definitions in the Summary View

-   **Add-On** - The overarching name of the add-on. E.g. T-shirt

-   **Variant** - The name of the variation of the main add-on. E.g. Medium T-shirt

-   **Status** - Whether the add-on is active or not.

-   **Sold** - The total number of the variant that has been sold.

-   **Inventory** - The total remaining inventory for the variant.

-   **Event** - The event, class, or collection to which the add-on belongs.
